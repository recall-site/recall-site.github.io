Documentation

How to use the app and write contracts in the RCL language.

Using the app

The sidebar gives access to the Home, Analysis, Batch and Documentation screens.

📝 Single analysis

  1. Open the Analysis tab.
  2. Select an .rcl file from your computer or paste the contract into the editor.
  3. Adjust the options (see below) and start the analysis.
  4. Review the result and metrics, and open the log or generated files from the quick actions.

The book icon next to the editor inserts language symbols at the cursor.

📚 Batch analysis

  1. Open the Batch tab.
  2. Choose a folder containing multiple .rcl files.
  3. Set the global batch settings.
  4. RECALL processes the files in parallel and writes a batch_results.csv summary in the same folder.

Analysis options

Automaton export

Choose don't export (fastest), the standard automaton, the minimal one (smaller and optimized) or both. Files are generated as .dot, the Graphviz format.

Pruning

Applies aggressive pruning to reduce the model size. Recommended for large contracts.

Max concurrent actions

Sets the maximum number of concurrent relativized actions (default: 30). Values that are too high can cause high memory usage or failures if system resources run out.

Result

When finished, RECALL reports whether the contract is conflict-free ([CONFLICT-FREE]) or, when there is a conflict, the state where it occurs, the state trace and the clauses involved. The result screen also shows execution time, automaton size and memory used, with shortcuts to the result, the full log, the .dot files and the table of symbols.

The RCL language

RCL (Relativized Contract Language) describes contracts between several parties through obligations, permissions and prohibitions that can be relativized: {A,B} means that A has the duty, permission or prohibition towards B.

Contract structure

A contract starts with the declaration of the conflicts to check, followed by the clauses. Every item ends with ;.

/* block comments */  // or line comments
conflict{
   global{(actionA,actionB), (actionC,actionD)};     // pairs of mutually exclusive actions
   relativized{(actionE,actionF)};                   // same, considering the parties involved
};

{partyA,partyB}O(action1);                      // A is obliged, towards B, to do action1
{partyA,partyB}P(action2);                      // A is permitted, towards B, to do action2
{partyB}F(action3);                             // B is forbidden from doing action3

The global and relativized blocks are optional. Identifiers must start with a letter and may contain letters, digits and _.

Symbol reference

The same reference is available inside the app, via the book button of the editor on the Analysis screen.

Contract Structure

conflict { ... };
Conflict declarationDeclares which actions should be checked as conflicting, globally and/or relative to the parties involved.
;
End of clauseTerminates a clause or the conflict declaration. Every rule must end with it.

Deontic Operators (Rules)

{A,B}O(action);
ObligationA is obliged, relative to B, to perform "action". Use {A} instead of {A,B} for a non-relativized (global) obligation.
{A,B}P(action);
PermissionA is permitted, relative to B, to perform "action".
{A,B}F(action);
ProhibitionA is forbidden, relative to B, from performing "action".
_/ clause /_
PenaltyOptional consequence attached to an obligation or prohibition: applies if it is violated. Written right after the O(...) or F(...) term.

Dynamic Clause

{A,B}[β](clause);
Dynamic updateAfter the action sequence β happens, "clause" becomes the new rule, relative to A and B.

Action Operators

+
Choice"a+b" means: do a, or do b.
.
Sequence"a.b" means: do a, then do b.
&
Concurrency"a&b" means: do a and b at the same time.
*
IterationOnly valid inside a dynamic clause's [β]. "a*" means: repeat action a zero or more times.
!
NegationOnly valid inside a dynamic clause's [β]. "!a" means: any action other than a.
1
SkipRepresents an empty action (a no-op).
0
ViolationRepresents a violating action.

Clause Connectors & Literals

^ (or AND)
ConjunctionCombines clause terms that must all hold at the same time.
| (or OR)
DisjunctionCombines alternative prohibition terms.
- (or XOR)
Exclusive alternativeCombines alternative obligation/permission terms: exactly one applies.
true
TrueA clause term that always holds.
false
FalseA clause term that never holds.
